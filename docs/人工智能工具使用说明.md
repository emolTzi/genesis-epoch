### 2.0 开发方式：人工定框架，AI 补重复

作品的代码不是“交给 AI 一键生成”的。实际做法是：

1. **人工搭框架**：由团队确定分层结构（数据 / 模拟 / 智能 / 表现 / 体验）、模块边界、命名约定与数据格式，先写出可运行的骨架和 2–3 个示例模块。
2. **人工写示例**：把示例模块写成“样板”——一个参数滑杆、一个判定函数、一个渲染对象、一条测试用例，连同注释与错误处理一起定稿。
3. **AI 模仿扩展**：把样板与接口约定交给 AI，让它按同一模式批量生成重复性代码（其余滑杆、其余判定项、其余渲染对象、其余测试用例）。
4. **人工逐条校验**：团队对照样板检查每一处 AI 产出，修正偏差、补写关键逻辑，再跑测试与实机验收。

这条流程决定了 AI 的产出集中在“同构、可对照”的重复部分；模块边界、关键算法与验收标准由人工掌握。仓库中同名模块的写法高度一致，本身就是这套流程的痕迹。

## 三、人工筛选与修改

## 四、作品运行时使用的大模型（可选功能）

| 项目 | 内容 |
|---|---|
| 功能 | “观测者·零号”：把观众的自然语言问题翻译成参数提议；把引擎推演结果讲成人话；在线模式下为新文明取名 |
| 接入方式 | OpenAI 兼容接口，由观众在设置中填写服务地址、模型与 API Key（作品不内置任何 Key）。预置选项：DeepSeek、通义千问、智谱 GLM、Kimi，均为国内服务 |
| 系统提示词 | 见源码 `src/llm/observer.ts` 中的 `PLANNER`、`EXPLAINER` 与取名提示词 |
| 约束 | 大模型输出的参数提议必须通过校验闸门（`src/llm/schema.ts`）：参数必须在注册表中、类型正确、落在范围内（越界夹回并说明）、观众持有对应钥匙。所有数值由确定性引擎计算，解释时只能引用引擎结果与资料库，理论问题只能引用理论库中的标准表述 |
| 离线兜底 | 没有网络或 Key 时，使用规则意图解析与预置回答（`src/data/offline.ts`），不调用任何大模型 |

## 六、版权与数据合规

- 作品（可运行文件）不包含任何由 AI 生成的图像、音频或视频。地球影像为 NASA 公有领域资料，声音全部由 Web Audio 实时合成。
- 文档中的封面、章节扉页、概念图与文创效果图由 ChatGPT 生成，均在图上与图注中标注“AI 生成”；数据图由作品引擎计算、Python 绘制，界面图为实机截图。
- 运行时不收集观众数据；墓园记录、留言与大模型配置只保存在观众本机浏览器中。API Key 默认只保存在当前会话。
- 不使用任何现有科幻作品的专有名词、角色与原文。
