5.4代码与文档的一致性

技术文档最容易失效的地方是“文档里的数字早就不对了”。本项目用三条机制压制这种漂移：

  1. 单一数据源：src/data/params.ts 的参数注册表同时驱动滑杆范围、引擎校验、LLM 闸门与附录的参数表；改动一处，四处同时生效。
  2. 文档由脚本生成：npm run docs 重新计算并写出《参数与文献》《关键数值》《旁白文稿》《知识卡》等数据类文档，本文附录 A、B 也由同一注册表在构建 PDF 时渲染。
  3. 图表由引擎导出：scripts/figdata.ts 调用引擎计算结果，scripts/figures.py 只负责绘图，不写死任何数字。

因此，若代码变更后未重新生成文档，npm run docs 的 diff 会直接暴露出来；这也是我们把文档生成放进日常构建而不是只在提交前手动整理的原因。
