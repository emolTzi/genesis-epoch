四条互相牵制的工程约束塑造了全部技术选型：单文件离线、确定性可复现、实时 3D、可核验。本章说明这四条约束如何落地，并给出代码规模、目录职责与构建流水线。

1.1设计目标与工程约束

约束要求实现手段
单文件离线展厅与机房的电脑可能没有网络、也不允许安装软件；评委双击文件就要能跑Vite + vite-plugin-singlefile 把脚本、样式、字体子集、NASA 影像与 worker 全部内联进一个 HTML；运行时零网络请求
确定性可复现同一宇宙编号、同一组参量必须得到同一部编年史，评委可交叉核对模拟层全部为纯函数；随机数按“宇宙编号 + 用途”派生子流（core/rng.ts）；沙盘回溯采用从头确定性重放，而不是快照回滚
实时 3D桌面集成显卡上稳定可看；展厅大屏可无人值守循环程序化着色器代替贴图与模型；粒子按画质档位缩放；帧率连续两次低于 38 自动降档；离屏暂停渲染
可核验界面上显示的、引擎算出的、文档里写的必须是同一组数字单一参数注册表驱动滑杆、判定、LLM 校验与文档生成；npm run docs 重算并重排文档数据

四条约束之间存在真实冲突：程序化渲染省掉了贴图体积，却把成本转移到着色器编译与逐像素计算；确定性重放省掉了快照内存，却要求每次回溯都从头跑一遍沙盘。第 2.5 节与第 2.10 节分别说明这两处取舍的量化结果。

1.2技术栈与依赖边界

层面选型理由与边界
语言TypeScript（严格模式，tsc --noEmit 作为构建闸门）模拟层是纯函数集合，类型即文档；严格模式在编译期拦住单位与空值错误
构建Vite 8 + vite-plugin-singlefile产物只有一个 HTML；开发期保留 HMR，构建期内联全部资源
渲染three.js（WebGL2）直接使用引擎自带能力，不引入后处理框架：Bloom 用自带 UnrealBloomPass，动画用自写补间调度器
测试Vitest与 Vite 共用转换管线，测试可直接 import 模拟层源码，不需要打包
文档生成tsx + 自写脚本（scripts/gen-docs.ts）从注册表与引擎重新计算并生成参数表、关键数值、旁白文稿，避免文档与代码漂移
智能层OpenAI 兼容的 chat/completions（可选）只负责“把自然语言翻译成参数提议”，不参与数值计算；无网络时由规则引擎兜底

依赖边界是本文反复强调的一条工程纪律：sim/ 不 import three，也不触碰 DOM；llm/ 不 import sim/ 的计算函数，只能提交“提议”；render/ 只读状态，不修改状态。三处边界由 ESLint 之外的物理手段保证——模拟层的单元测试在 Node 环境下直接运行，一旦误引 three 或 DOM，测试会立刻报错。

1.4构建、打包与交付形态

npm install        # 仅 1 个运行时依赖（three），其余为构建与测试工具
npm test           # 63 项单元测试
npm run build      # tsc --noEmit && vite build → dist/index.html（单文件，1.67 MB）
npm run docs       # 从注册表重算并重新生成数据类文档

构建管线有三处值得说明的细节：

  1. 字体子集化：scripts/build-fonts.py 扫描源码中实际出现的字符，把思源宋体压到约 416 KB、JetBrains Mono 压到约 30 KB，再以 data URI 内联；这是单文件体积能控制在 1.7 MB 的关键。
  2. worker 内联：文明沙盘的微观抽样跑在 Web Worker 里，构建时把 worker 源码编译成字符串并以 Blob URL 注入，避免额外的 .js 请求。
  3. 影像内联：终章使用的 NASA 公有领域地球昼夜影像预先压成两张小尺寸纹理，同样以 data URI 内联。

交付形态因此收敛为“一个 HTML + 一份许可证目录”：拷到任何一台装有新版 Chrome 或 Edge 的电脑，双击即可运行，不需要服务器、不需要联网、不需要安装运行时。
